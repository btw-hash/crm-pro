New SKU / Initial qualification: a task trigger (#218)

domain use-case server action UI

The problem

When a new product is added to the catalog, a manager has to remember on their own that qualification needs to start. There was no path from "new SKU" to "a deal in qualification" — only manually creating a deal from scratch. On the 2026-06-25 call this question stayed open: "who/what initiates → for which client → what happens next" (1:12:57–1:17:18).

Solution: an explicit process path

Catalog /products
the sales rep sees the product
→
"Plan launch for client"
picks a client
→
Deal: New SKU: <name>
goal=new_sku, stage=qualification
→
Production audit
→
Test / trial
→
Proposal calc

Initiated by: a sales rep or the head of sales, from the product catalog.
Client link: an explicit choice in the form — the initiator sets the task for a specific client they plan to bring the SKU to.
Owner: the current user (whoever clicked).
Deal name: automatically "New SKU: <product name>".

Before / After

Before
  • No trigger — only a manual "Create deal" from scratch
  • You had to manually type the name, pick the new_sku goal, and the client
  • The process was opaque: there was no "SKU → deal" link in the system
After
  • From the product card → "Plan launch for client" → pick a client → done
  • The deal is created automatically: goal new_sku, stage qualification
  • The name includes the SKU's name — searching deals is transparent
  • A link to the new deal appears immediately

  • The button is visible to: sales rep, head of sales
  • A technologist and a category manager don't see the button (they only read the catalog)
  • A sales rep creates the deal for themselves — automatically the owner
  • A sales rep's client list is scoped to their own portfolio (listClients with owner-scope)
