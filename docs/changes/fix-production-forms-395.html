Production: editing forms

Issue #395 · fix/production-forms-395 · 2026-06-29

Summary

Two items of the "Production" epic have been implemented:

  • fix [15] Production audit — added an edit mode for a saved audit.
  • fix [16] Test/sample batch — fixed the sample-add error + added an edit mode for the quantity.

[16] Root cause of the sample-add error and the fix

What was broken

In requestSampleAction (actions.ts), the catch block did not handle DealNotFoundError: 

catch (cause) {
  if (cause instanceof InsufficientStockError || cause instanceof SampleRequestStageError) {
    return { ok: false, error: cause.message };
  }
  throw cause;  // ← DealNotFoundError bubbled up as a 500
}

In addition, under Turbopack/Next.js instanceof is unreliable between "use server" and SSR bundles (documented in neighboring actions). For InsufficientStockError and SampleRequestStageError there was no fallback by .name, so under a certain build configuration these errors also fell through to throw cause and produced a 500 instead of an inline message.

How it was fixed

catch (cause) {
  if (
    cause instanceof InsufficientStockError ||
    cause instanceof SampleRequestStageError ||
    cause instanceof DealNotFoundError ||
    (cause instanceof Error &&
      (cause.name === "InsufficientStockError" ||
        cause.name === "SampleRequestStageError" ||
        cause.name === "DealNotFoundError"))
  ) {
    return { ok: false, error: cause.message };
  }
  throw cause;
}

Now all three domain errors are returned as { ok: false, error } — shown inline in the form, they no longer produce a 500.

[15] Editing a production audit

Before

After the audit was saved, the Equipment and Client pain points fields were shown read-only. To fix a data-entry mistake you had to create a new audit (the same record got overwritten via upsert).

After

When the "Production audit" section is active (auditVis === "active") and an audit already exists — instead of a read-only card, a pre-filled AuditForm is shown with the current values (edit mode). Saving calls updateAuditAction → updateProductionAudit use-case → AuditRepository.update().

[16] Editing a sample request

Before

The list of requests was shown read-only. It was impossible to change the reserved quantity without re-creating the request.

After

In the "Test batch / samples" section (when active), a collapsible "Edit last request" element appears below the add form. Inside is a form with the current quantity that calls updateSampleAction → updateSampleRequest use-case. The product and technologist do not change (the reservation in the ERP has already been made).
