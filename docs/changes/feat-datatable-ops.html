#321 · Unified DataTable for operational screens

One table component: filter + export + column sorting + pagination — consistent across all 9 screens.

What changed

9 operational screens repeated the same table block via copy-paste (glass panel, headers, rows, status badges) — each with its own ~150 lines of markup, no sorting or pagination. Introduced one reusable component DataTable (src/app/_components/data-table.tsx) and migrated every screen to it: Procurement, Assortment, Shipments, Add-on requests, My shipments, Accounting, Logistics, Packing, Defects. Added click-to-sort column headers and pagination — where neither existed before. Working filters (?filter=) and exporting the filtered selection to CSV are preserved. Closes #321 (and removes the duplication flagged in #312/#313).

Live demo — sorting and pagination

Click the column headers (click again to reverse order). Paging controls are at the bottom. This behavior is now identical across all 9 screens.

Before → After

Before

Every screen had its own copy-pasted table. No sorting anywhere; as demo data grew, long lists had to be scrolled through entirely (no pagination). Filter/export were fixed screen by screen (#312, #313) — 9x the work and a risk of drift.

After

One DataTable<T>: column config, ready-made cells (text, badges, action buttons), sorting on any column, pagination at 12 rows per page. Filter and export are unchanged. Cells are prepared on the server; sorting happens client-side on numbers/strings.

Reproduction steps

  1. Log in as head of sales (alexander) or category manager (buyer).
  2. Open /procurement (Procurement) → in the "Quotas by manager" table click the "Available" header — rows sort ascending, click again for descending (↑/↓ arrow on the active column).
  3. Open /assortment (Assortment analytics) → sort by "Gross margin" or "Units"; toggle the filter chip (Grow/Hold/Stop) — sorting and filter work together.
  4. Open /packing, /logist, /defects, /accounting → row action buttons ("Next stage", "Truck left", etc.) work as before; sorting/pagination were added.
  5. On any screen click "Export" — the CSV contains the current (filtered) selection, as before.
  6. If there are more than 12 rows — a "‹ ›" pager appears at the bottom of the table with the range "1–12 of N".
