Clients RBAC + revived controls (clients / notifications / onboarding / analytics)

fix · PR for issue #369 · refs #317 · branch fix/clients-deadcontrols

A batch of findings from a demo QA pass: operational roles could see the commercial client base, and several controls on various screens were "drawn" but did nothing. Fixed six items.

What changed

  1. Clients RBAC (main fix). The client base section (AR, credit limit, prices) is now available only to commercial roles — Head of sales, Manager, category manager. Accounting, Logistics, and Technologist get a redirect to the home page on /clients, and the "Clients" item is removed from their menu. A new predicate canSeeClientBase(role) is the single source of truth (page + sidebar).
  2. Working client search. The "Search clients" field was a decorative <div>. It's now a GET form → ?q= (SSR, like the filters): case-insensitive name search, the active segment filter and the query persist together.
  3. "Create task" on the client card. The button led to /deals, where the create form only opens for Manager/Head of sales — everyone else hit a silent dead end. Hid the button for roles without deal-creation rights (canCreateDeal).
  4. Notifications — filter chips. "All / New / Read / By task" were dead <button> elements. Switched to the shared OpsFilters → ?filter= (like the ops screens): the list actually narrows by status/task-link.
  5. Onboarding — "Export" and chips. These were stubs. "Export" is now the shared ExportButton (CSV of the current selection), the "All / Gathering documents / Under negotiation / Approved" chips are the shared OpsFilters with ?filter=.
  6. Analytics — "AI insight" card. The "Ask the assistant" button had no handler — it's now a <Link href="/assistant"> (shown only to those who can actually open the assistant — Head of sales). The insight text is honestly labeled as an example ("AI insight · example" + caption). Charts/breakdown/period/export were untouched.
Why the RBAC is like this: the client list with financials is a trade secret (see docs/DATA_POLICY.md), not operational data. Accounting/Logistics work within their own scope (orders/shipments), the Technologist works with the test queue; none of them need the commercial client base.

Repro steps

  1. npm run dev.
  2. Log in as an accountant (or logistics) → the "Clients" menu item is absent; navigating directly to /clients redirects to the home page.
  3. Log in as a Manager or Head of sales → "Clients" is there; type part of a name (e.g. "Barry") into the "Search clients" field + Enter → the list narrows; switching a segment chip preserves the query.
  4. Log in as a category manager → "Clients" is accessible (procurement), but the client card has no "Create task" button; a Manager/Head of sales has one and it leads to the form.
  5. Notifications → click the "New / Read / By task" chips — the list actually filters (the URL changes to ?filter=…).
  6. Onboarding → the status chips filter the list; "Export" downloads a CSV of the current selection.
  7. Analytics (Head of sales) → the "AI insight · example" card, the "Ask the assistant" button leads to /assistant. A Manager has no button (head-only section).
