Real web search + AI analysis of results

The head of sales's assistant now HELPS (analyzes what it found) instead of dumping a raw list of links

What was built (closes #281)

  • Real general web search is now connected — the Brave Search API, behind the existing WebSearchGateway port. By default everything stays on a deterministic stub (WEB_SEARCH_MODE=stub).
  • KEY CHANGE: on a web question ("find cocoa suppliers", "who's in the market"), the assistant no longer dumps a raw list of links — what it finds is analyzed by our AI in CRM Pro's business context: what's relevant to us (ingredient distribution) and why, what to check next; sources (URLs) at the end.
  • The AI relies ONLY on the snippets it found — it doesn't invent numbers or facts (a project rule). If the search found nothing, it's an honest "nothing found", and the AI isn't called.
  • The demo stub also produces meaningful text (a brief summary of the results + links), not a single list line.

Before → after

Web question to the assistant Before After
Result source Stub only (fixed demo links) Real Brave Search API when WEB_SEARCH_MODE=live; the stub is the default
What the head of sales sees A raw "• Title / snippet" list — figure it out yourself An AI breakdown: which options are relevant to us and why, what to check next + sources
AI layer contract Only answers from the CRM snapshot (answerManagerQuestion) New method AiGateway.answerFromWebSearch (analyzes snippets in CRM Pro's context)
Empty result "nothing found" "nothing found" (the AI isn't called — nothing to analyze)

How to verify (on the stub, no keys)

  1. Log in as Alan (head of sales), open the assistant chat.
  2. Ask "find new ingredient suppliers" — the question is recognized as a web search (not a CRM-snapshot query).
  3. On the stub, the answer is a brief summary: "Found N sources… key ones: … worth checking relevance to us" + a list of links (not a single list line).
  4. Live mode (separately, via env): WEB_SEARCH_MODE=live + WEB_SEARCH_API_KEY + AI_MODE=live — then the search goes to the Brave Search API, and the results are analyzed by our AI in context.

Note for production (Brave API key)

The adapter is resilient: on any failure (missing/invalid key, network issue, malformed response) it silently returns an empty list (the assistant gently says "nothing found"); the API key is never written to logs.
