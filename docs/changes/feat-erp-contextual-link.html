The "Open in ERP" link — brought back contextually, on the deal and client cards

feat(ui) · PR #272 · closes #271 · branch feat/erp-contextual-link

What changed

  • The link to the ERP used to live in the global header (present on every screen — irrelevant on Analytics/Assistant) and disappeared entirely during the #263 redesign. We're bringing it back contextually — only where it makes sense: on the deal and client cards.
  • A new server component ErpLink (src/app/_components/erp-link.tsx) — a link to the ERP window using the address from the ERP_UI_URL env var. If the env var isn't set → it renders null (no button, nothing breaks).
  • Deal card /deals/[id] → "Open order in ERP" (gated by showCommercial). Client card /clients/[id] → "Open counterparty in ERP" (gated by showPrice), next to the "Create deal" button.
  • ERP_UI_URL was added to the env schema (zod, optional).

Before → after

Where Before After
Header (all screens) An ERP button on every screen, including irrelevant ones; disappeared after #263 No button in the header (removed from the global layout)
Deal / client card No link to the ERP A contextual "Open order/counterparty in ERP" link (role-gated)
Home / Catalog / Analytics — No link (not relevant — isn't rendered)

Repro steps

  1. Set ERP_UI_URL=https://... in .env, run npm run dev, log in as the head of sales.
  2. Open Deals → any deal (won/in progress) → below the card's header there's an "Open order in ERP" link (opens in a new tab).
  3. Open Clients → any client → next to "Create deal" there's an "Open counterparty in ERP" link.
  4. Go to Home / Catalog / Analytics — the "Open in ERP" link isn't there.
  5. Remove ERP_UI_URL from env and restart — the link disappears everywhere (nothing breaks).

Verified

  • In the browser (dev, ERP_UI_URL set): the link IS there on the deal and client cards; it's NOT on Home/Catalog/Analytics.
  • npm run verify green (108 files, 582 tests).
