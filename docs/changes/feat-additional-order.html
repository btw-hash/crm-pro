Add-on requests outside business hours

Issue #217 · feat/additional-order · crm-pro

Business context

A client places an add-on order late at night or early in the morning. The manager records the extra line items and links them to an already placed/shipped request from the same day — an "add-on request." The warehouse picks the extra items, and the shipment goes out with no delay.

Client calls at 11 PM
→
Manager records the add-on request
→
Linked to the day's request (e.g. SO-2026-0006)
→
Warehouse picks the extra items in the morning
→
Ships the same day

Before this feature: the concept of an "add-on request" didn't exist in the system. The manager created a separate request with no link to the parent one, the warehouse had no context, and confusion followed.

What was implemented

Domain layer

New domain: src/domain/shipment/additional-order.ts

  • Entity AdditionalOrder — id, client, parentOrderNumber, line items, ship date, who recorded it, time recorded, note.
  • Factory createAdditionalOrder — validation: parent request number, ISO date, at least one line item, quantity > 0, non-empty item name.
  • isSameDayAsParent — the "same day" business rule.
  • additionalOrderLinesSummary — formats line items for tables.

TDD: 14 tests — all validation cases, formatting, the "same day" business rule.

Application + Infrastructure

  • Port AdditionalOrderRepository — save, findById, listByDate, listByParent.
  • Use cases: makeCreateAdditionalOrder, makeListAdditionalOrdersByDate, makeListAdditionalOrdersByParent, makeGetAdditionalOrder.
  • In-memory repository — filters by date and parent order.
  • Composition root — additionalOrders repository + 3 use cases in AppContainer.

UI — /shipments/additional

A new page for the manager (role mop) and head of sales (head).

  • Quick form: client (select), parent request number, ship date, line items (name + qty + unit), note.
  • Table of today's add-on requests: parent request with an "add-on" badge, client, line items, who recorded it, time recorded (can be overnight).

New role predicate: canFileAdditionalOrder → mop | head (the technologist and category manager don't file add-on requests).

Sidebar: new "➕ Add-on requests" item for mop + head.
