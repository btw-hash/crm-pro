Multi-item proposal

Branch feat/multi-item-proposal · a proposal now covers several product line items

What changed

  • A proposal is assembled from several product line items (previously — one). Matches the distributor's real process: 20–30 line items in one proposal.
  • Line items can be added and removed; a total across all line items is calculated.
  • PDF export and saving to the deal feed are now multi-item.
  • Clean architecture is respected (domain → application → infrastructure → app), 197 tests green, typecheck + lint + format clean. The numbers are deterministic (the ERP's price × quantity), AI never invents them.

Before → after

Before

A proposal = one line item: one product + a quantity. The calculation and the PDF covered only a single product. Didn't fit a real proposal with dozens of line items.

After

A proposal = a list of line items (product + quantity for each). A "+ Add line item" button and row deletion. The total = the sum across line items that have an ERP price. The preview table, the PDF, and the feed summary — all cover every line item.

Repro steps

  1. Start the app: npm run dev → open http://localhost:3000.
  2. Go to /deals, open any deal (the card /deals/[id]).
  3. Find the proposal-building block (a form with a product picker and a "Build proposal (AI)" button).
  4. Pick a product and enter a quantity for the first line item.
  5. Click "+ Add line item" → add a second product with a quantity. Repeat for 3–4 line items.
  6. Remove one line item with the "✕" button — the row disappears, the rest stay.
  7. Fill in the monthly output and defect rate before/after, click "Build proposal (AI)".
  8. See the proposal card: a table with a row per line item (product, quantity, price, line total) + a "Total" row across every line item.
  9. Click "📄 Export to PDF" → the same multi-item table with the total is in the PDF.
  10. Click "💾 Save to deal" → a note listing every line item appears in the deal's feed.

Edge case: a product with no individual price in the ERP — its row shows "—" and isn't included in the total; if no line item has a price, the total is empty (not 0).
