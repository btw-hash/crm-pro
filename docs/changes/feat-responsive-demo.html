Responsive layout for top screens on phone and tablet

Branch feat/responsive-demo · layout only, business logic and the desktop view were not changed.

What changed

On narrow screens (phone, tablet in portrait), content overflowed past the right edge — a horizontal scrollbar appeared, cards and charts got clipped, the sidebar took up too much space. The demo's top screens now stack into a single column, and the side menu collapses into a thin rail.

Before → horizontal scroll up to +428px on phone (analytics), +231–319px on the other screens.

After → 0px of overflow at 390px, 768px, and 1440px.

Horizontal overflow measurements

Screen Phone 390px Tablet 768px Desktop 1440px
Home / Board +231 → 0 0 → 0 0 → 0
Analytics +428 → 0 +50/64 → 0 0 → 0
Add-on requests +251 → 0 0 → 0 0 → 0
Assistant +319 → 0 0 → 0 0 → 0

How it's built

  • Fixed multi-column grids → repeat(auto-fit, minmax(Npx, 1fr)): columns collapse into one on narrow screens on their own, the column count on desktop is preserved.
  • Control rows (Slice/View/Export, form fields) — flex-wrap.
  • Fixed widths (the assistant history panel, 264px) → max-width: 100%.
  • @media (max-width: 768px) in globals.css: the sidebar → a thin icon rail (64px), reduced content padding, an overflow-x: hidden guard.

Repro steps

  1. Open the app and narrow the browser window to phone width (≈390px) — or DevTools → device toolbar.
  2. Go through Home → Analytics → Add-on requests, and as head of sales — Board and Assistant: content is in a single column, no horizontal scroll, the sidebar is a thin strip of icons.
  3. Return the window to desktop width (1440px) — the layout is unchanged.

Processes (kanban) were intentionally left untouched — the board has its own horizontal scroll. Login was not changed.
