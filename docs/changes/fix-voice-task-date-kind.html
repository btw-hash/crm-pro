Voice-dictate a task (AI): the right kind and due date

"Tomorrow call Marina at 5" → kind "Call" + due date tomorrow, the time stays in the step's text

What changed

  • AI parsing of a dictated task now understands not only "a summary of a call/meeting that already happened", but also a future reminder task ("tomorrow call Marina at 5"). The kind is determined by the action: "call/phone" → Call, "go see/meet" → Visit, otherwise Note.
  • The next step's due date is set automatically from what was said: "tomorrow", "the day after tomorrow", "in a week", "on Friday", "July 5th", "the 5th" → a specific day in the date field. The human checks it and corrects it if needed.
  • The time of day ("at 5 pm") stays in the next step's text — the date field holds only the day.
  • The project principle is upheld: the day is computed by deterministic code (resolveRelativeDueDate), not the LLM — dates aren't invented; a human confirms.

Which due-date phrasings are recognized

Said Due date (if today is Tue, 2026-06-30)
today / tomorrow / the day after tomorrow 2026-06-30 / 2026-07-01 / 2026-07-02
in 3 days · in a week · in 2 weeks · in a month 2026-07-03 · 2026-07-07 · 2026-07-14 · 2026-07-30
on Monday … on Sunday (also "by Tuesday", "before Friday", "next Wednesday") the nearest future occurrence of that day
July 5th · March 15th (already past) · the 5th 2026-07-05 · 2027-03-15 · 2026-07-05
only a time ("at 5 pm") / past ("yesterday") / no due date no date is set — the human sets it themselves

How to verify

  1. Open any process: "Processes" → card → "Voice-dictate a task (AI)" section.
  2. Type (or dictate) Tomorrow call Marina at 5 pm → click "Recognize with AI → task".
  3. Confirm: Kind = Call; Next step due date = tomorrow; the step's text still has "at 5 pm".
  4. Edge case: On Friday go see the technologist for a tasting → Kind = Visit, Due date = the nearest Friday.
  5. "Confirm and save" → an activity + a task with a due date appear in the feed.
