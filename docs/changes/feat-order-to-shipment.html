#397 · Customer order → Shipment

Once an order is placed in the ERP, a Shipment record is created automatically and its status is visible on the process card

Flow

"Won" process → placeCustomerOrder → ERP: createCustomerOrder → Shipment (placed) + DealEvent order_placed

Idempotency: a repeated call with the same dealId doesn't create a second Shipment (key order:<dealId> in the ERP).

Process card — "Customer order (ERP)" section

Before After
"OrderComposer" form / placeholder "Placed after the deal is won" If a Shipment already exists — a status block: "Order No. CO-0001 placed. Shipment status: Accepted. Date: 2026-07-01 · address: Portland, OR"
The OrderComposer form is hidden after the order is placed — a duplicate order can't be created through the UI

  • Application use cases: makePlaceCustomerOrder — creates the Shipment + DealEvent; makeGetDealWorkspace — includes the linked shipment
  • Infrastructure: InMemoryShipmentRepository.findByDealId, PrismaShipmentRepository.findByDealId + upsert with dealId
  • Migration: 20260629000000_add_shipment_dealid — additive, nullable
  • UI: deals/[id]/page.tsx — conditional render of the shipment status
  • Server action: placeOrderAction passes actorId + revalidatePath(/shipments, /my-shipments)
