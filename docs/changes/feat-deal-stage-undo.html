Deal stage undo (revert)

Branch feat/deal-stage-undo · a manager can fix a mistaken transition and move a deal back through the pipeline

What changed

  • Forward transitions through the pipeline — unchanged, the forward guard is not weakened.
  • An explicit "Revert stage" operation was added: drag the card into an earlier column or press the ↩ button on the card.
  • Reverting asks for a reason (optional) — recorded in the event feed for the head of sales.
  • Domain: a new function canRevert(from, to) — allows only an earlier open stage (not won/lost).
  • Feed: a new event type stage_reverted with the label "Stage reverted" and the reason text — pipeline analytics aren't broken.
  • 274 tests green, typecheck + lint + format clean.

Before → after

Before

Dragging a card into a column with an earlier stage was silently ignored (canTransition returned false, there were no backward buttons). A wrong transition could not be fixed without directly touching the database.

After

Dragging backward opens a dialog for the reason and reverts the deal. The card now has ↩ <Stage> buttons for every valid revert target. The event feed shows the revert with the "Stage reverted" label, from→to arrows, and the reason.

Repro steps

  1. Start the app: npm run dev → open http://localhost:3000.
  2. Go to /deals (the kanban pipeline). Find a card at a stage past "Qualification" — for example "Production audit".
  3. Forward transition: click the → Proposal calc button — the card optimistically moves to the "Proposal calc" column. Or drag the card right into the desired column.
  4. Revert via button: on the card in "Proposal calc" click ↩ Production audit. A "State the reason" dialog opens — enter text or leave it empty and press OK.
  5. The card optimistically moves back to "Production audit". If a reason was given — the server logs it in the deal's feed.
  6. Revert via drag: grab the card and drag it into an earlier column — the same reason dialog appears.
  7. Open the deal card (/deals/[id]) → the "Event feed" block. See an entry with the "Stage reverted" label, from → to arrows, and the reason text (if given).
  8. Boundary check: try dragging a card to Won or Lost via revert — this should not work (terminal stages). Drag a deal from "Qualification" — there should be no ↩ buttons (nothing to revert to).

The revert reason is optional. Pressing "Cancel" in the dialog aborts the operation with no changes.

Triggers (auto-task for the sales rep, notification) don't fire on a revert — it's an explicit correction, not the normal forward progress through the pipeline.
