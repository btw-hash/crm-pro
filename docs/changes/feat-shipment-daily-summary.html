Daily shipment summary report

A link in the order → warehouse → delivery chain: the system rolls up the day's totals itself, a human just confirms

What was built (partially closes #128)

  • The "Shipment & delivery" page now has a "Daily summary report" section — placed exactly between "Warehouse letter" and "Delivery schedule" (as described in the issue: letter → summary report → schedule).
  • For each shipment date, there's a card with the day's totals: total weight, number of shipments, clients, trucks involved, plus "unassigned truck" and "delivered", and a table of order / client / address / weight / truck / stage.
  • Everything is computed deterministically from orders (a pure domain function), not by AI. The system collects the numbers — a human only confirms them (passive capture).
  • The section is available to operational roles (procurement/category manager, head of sales).

Before → after

"Shipments" section Before After
Document chain Warehouse letter → straight to the delivery schedule (the middle link was empty) Warehouse letter → daily summary report → delivery schedule
Daily totals Not computed anywhere — a manager would have to tally weight/trip count by hand Day card: weight, shipments, clients, trucks, unassigned, delivered
Number source — Deterministic aggregation from orders (a pure function, covered by tests)

Why

The main business pain is manually re-typing data between departments. Before delivery, someone still has to roll up "how much are we shipping today, on how many trucks, to whom." Now the system builds that rollup itself from orders — the department just needs to look and confirm, not recompute it.

How to verify

  1. Start the dev server and open the "Shipments" section (head of sales/procurement role).
  2. Below "Warehouse letter" there's now a "Daily summary report" block — one card per shipment date.
  3. For 2026-06-25 the daily total shows 880 kg, "2 shipm. · 2 clients · 1 truck" (two shipments on one truck are merged).
  4. For 2026-06-27 the total shows "0 trucks · unassigned: 1", and the row shows "— not assigned —" (a shipment with no driver).
  5. For 2026-06-23 — "delivered: 1": the report reflects what actually happened that day, so it includes delivered shipments too (unlike the delivery schedule, which doesn't).
