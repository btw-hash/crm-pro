"Head of Sales" quick login works again

fix(auth) · PR #270 · closes #268 · branch fix/login-pill-nested-forms

What changed

  • Login via the "Head of Sales" pill on /login failed with "invalid username or password", even though the password was correct. The other roles (Manager/Technologist/Procurement) worked.
  • Cause — invalid HTML, not the password. The quick-login pills (each its own <form>) sat inside the login card's main <form>. When parsing, the browser merged the first nested form (Head of Sales) into the parent → the card ended up with two username fields (an empty visible one + a hidden alexander), and formData.get("username") took the first one = empty → InvalidCredentials. It was exactly the first pill that failed.
  • Fix: the login card is now a <div>, not a <form>. The email/password fields live in their own <form>, and each quick-login pill is a sibling form. No more nested forms.

Before → after

Scenario Before After
The "Head of Sales" pill (alexander) "Invalid username or password" → stays on /login Signed in → redirect to /
Login card markup Nested <form> (invalid HTML, a second username field) 5 non-nested sibling forms (nestedInForm:false for all)
Other roles (Manager/Technologist/Procurement) Worked (their pills happened to end up as separate forms) Still work as before

Repro steps

  1. npm run dev → open http://localhost:3000/login.
  2. Click the quick-login pill "Head of Sales" (at the bottom of the card).
  3. Result: signed in, redirected to Home as the head of sales (previously an "invalid login" error popped up here).
  4. Check the other pills (Manager/Technologist/Procurement) — all lead to / in their own role.

Verified

  • DOM inspection: 5 non-nested forms, all with nestedInForm:false.
  • All role pills → /; before the fix "Head of Sales" → /login.
  • npm run verify green (108 files, 582 tests).
