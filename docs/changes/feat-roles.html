Roles and access control

Unified model · 4 roles · based on roles-rbac + category manager and section guards

What was built

  • 4 roles: Head of sales, Manager, Technologist, Category manager/Procurement.
  • Data access — enforced directly in use cases: a Manager only sees their own portfolio, the head of sales sees the whole department; a technologist doesn't see margin/prices at all.
  • Section access — the sidebar is filtered by role, pages are guarded (no access → redirect to home): /procurement — category manager/head of sales, /tech-queue — technologist/head of sales, /analytics and /assistant — by permission.
  • Numbers are deterministic, AI doesn't invent them. Clean architecture is preserved.

Repro steps

  1. Run the app: npm run dev → open the address printed to the console (default http://localhost:3000).
  2. Open /login — it has quick sign-in buttons per role.
  3. Head of sales (alexander) → the sidebar shows EVERYTHING: clients, deals, analytics, assistant, procurement, tech queue.
  4. Manager (owens) → clients, deals (own portfolio), analytics, notifications. Procurement, tech queue, and the assistant are NOT in the menu.
  5. Technologist (kent) → tech queue + deals; doesn't see margin/prices or analytics.
  6. Category manager (buyer) → the "Procurement" section (quotas/deficit) + deals; no personal sales analytics or assistant.
  7. Guard check by URL: logged in as a Manager, open /procurement or /tech-queue directly → redirected to home (no access). Logged in as a category manager — /procurement opens.
