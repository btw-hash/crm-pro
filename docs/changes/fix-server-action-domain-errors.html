Domain errors no longer trigger a red "500" overlay

The audit form and other deal-card actions now report errors gently, inline

What changed (closes #232)

  • Bug (reproduced): on the deal card, saving an audit with empty fields threw a red Runtime overlay "Specify at least one piece of equipment or client pain point" — scary and confusing.
  • After: the same error is now shown as a gentle inline caption right in the form, the page doesn't crash; you can fix it and save right away.
  • Along the way: ran an adversarial audit across all 12 server-action files. No other overlays are reachable from the UI; hardened edge cases (tech queue, stage transitions) against crashing on malformed requests.
  • Side effect: the audit author is now recorded as the real user (previously a hardcoded stub).

Before → after

Scenario Before After
Empty audit → "Save" Full-screen red overlay (Runtime Error) Inline error below the form, page intact
"Take into work" on an already-taken request Risk of a 500 on an instanceof mismatch (Turbopack) Reliably caught → inline message
A malformed direct request to a deal action A plain Error → overlay A clean rejection, no crash

How to verify (main scenario)

  1. Sign in as Alan Peterson (Head of Sales) or the owner of a deal at the "Audit" stage.
  2. Open a deal at the "Production audit" stage (e.g. "Levara Sourdough Starter…").
  3. In the "Production audit" block, leave everything blank and click "Save audit".
  4. Below the form, "Specify at least one piece of equipment or client pain point" appears — no red overlay.
  5. Fill in "Equipment" (e.g. "Miwe rotary oven") → "Save" → the audit is saved and displayed.
