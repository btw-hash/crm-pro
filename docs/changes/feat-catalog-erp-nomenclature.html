The catalog now pulls nomenclature from the ERP + brought back the numeric stock level and expiration date

feat(catalog) · PR #277 · closes #276 · branch feat/catalog-erp-nomenclature

What changed

  • In the owner's words: "it's strange that the catalog works like an online store — we need data from the ERP." The cart logic is correct (the manager builds up a request), but the product list itself was hardcoded in the CRM, instead of coming from the ERP. Plus the #263 redesign hid the free stock number and the expiration date.
  • New port method ErpGateway.listNomenclature() — the nomenclature reference from the ERP. Implemented in the stub (seed) and in ODataErpGateway (the real Catalog_Nomenclature, mapped to the live ERP's $metadata).
  • ProductRepository.upsertMany() (in-memory + Prisma): upsert by id; items removed in the ERP are not deleted (deals have FKs pointing to them).
  • Use case makeSyncNomenclature() — ERP → DB sync: the ERP is the source of the list, CRM enrichment (Sales Kit) is preserved via a merge by id so the sync doesn't wipe it out. Run with npm run sync:erp (postgres/odata; a stub for testing the pipeline without the ERP). The catalog reads from the synced DB — "not realtime," as agreed on 06/25.
  • Catalog UI: brought back the numeric free stock level (N kg) and an "Expiration date" line on the product card.

Before → after

Aspect Before After
Product list source Hardcoded in the CRM (local repository) A synced reference from the ERP (npm run sync:erp)
Free stock on the card Only a status badge, no number (the redesign hid it) Status badge + exact "N kg" available
Expiration date Wasn't shown A "Expiration date: …" line (important for food products)
CRM enrichment (Sales Kit) — Preserved via merge — the ERP sync doesn't wipe it out

Repro steps

  1. Run the sync: npm run sync:erp (in stub mode it pulls from the seed nomenclature — products get populated, e.g. 0 → 9).
  2. npm run dev, log in as head of sales/procurement, open Catalog.
  3. See on the product card: a numeric free stock "N kg" next to the status badge and a "Expiration date: …" line.
  4. The product list — from the synced DB (not a hardcoded set in the CRM).

Verified

  • sync:erp against a real Postgres (ERP stub): products 0 → 9.
  • Sync unit test: the merge preserves the kit; an empty ERP doesn't delete items.
  • Catalog in the browser: stock as a number + expiration date.
  • npm run verify green (109 files, 584 tests).
