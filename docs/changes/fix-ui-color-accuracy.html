UI color inaccuracies

branch fix/ui-color-accuracy · CRM Pro's warm UI theme · from a client signal + a color audit (6 agents)

1. Card titles on the "Tasks" board — were red

All deal card titles (kanban and completed) were colored accent-red, even though titles are dark throughout the theme (like "Deal" in the drawer, tiles, login).

Before Collect receivables and a new shipment After Collect receivables and a new shipment

button.kanban__card-title: color: var(--accent-strong) → var(--fg). The hover underline (clickability) is preserved.

2. Catalog: "Task created" text — raw CSS green

The success message for launching a new SKU used the CSS keyword green (#008000) instead of the success token.

Before Task created — open After Task created — open

launch-sku-button.tsx: color: "green" → var(--success) (as everywhere else in the catalog).

3. Delete modal: "This action is irreversible." — an out-of-place gray

The caption was colored with a one-off cold #828c99, not used anywhere else.

Before This action is irreversible. After This action is irreversible.

deal-crud-controls.tsx: #828c99 → var(--muted).

Repro steps

  1. Open /deals ("Tasks") in any role → card titles are dark, not red.
  2. /products → "Launch new SKU" → the "Task created" message — green via the success token.
  3. /deals/[id] → delete a task → the "This action is irreversible." text — a warm muted gray.

The color audit confirmed the rest of the palette is disciplined. The systemic "cold gray #9a9ea8 instead of the warm --muted" (150+ places) is a consistent pattern from a 1:1 prototype rollout, a separate tokenization debt; left untouched here. Dead rules .assistant__who/.chip--alert (red, but unused anywhere) are left for a separate cleanup.
