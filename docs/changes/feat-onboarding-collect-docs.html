Onboarding: collect remaining documents for an existing package

branch feat/onboarding-collect-docs · following the client's question "how do we collect the rest of the documents?"

Problem

Package documents could only be set when onboarding was created. If it was started with 3 out of 6, there was no way to mark the rest: the list row showed static text ✓/✗, and the "Send to legal" button only appeared once all 6 were collected — the package would get stuck.

After

Documents in the row are now interactive toggle pills (for the "Collecting" and "Rework" statuses). A click marks/unmarks a document; the "N/6" counter updates; once all 6 are collected, "Send to legal →" appears.

Before (read-only, dead end)
✓ Company card · ✗ Power of attorney · ✗ Bank details
After (clickable) ✓ Company card ○ Power of attorney ○ Bank details

After it's sent to legal (Under review) and approved, the package is read-only — documents can no longer be edited.

How it's built (clean architecture)

  1. domain setDocumentCollected — immutable, only in collecting/rejected, validates that the document belongs to the package;
  2. use-case makeSetOnboardingDoc wired into composition-root;
  3. server action setOnboardingDocAction (RBAC for the sales role, catches the domain error);
  4. UI: a form + server action per document (works without JS), revalidatePath.

Repro steps

  1. Log in as a Manager (or head of sales) → the /onboarding section.
  2. On an onboarding record at "Collecting documents", click document pills — the counter increases (e.g. 4/6 → 5/6 → 6/6).
  3. Once all 6 are marked, the "Send to legal →" button appears.
  4. Clicking an already-collected item (✓) unmarks it again. Refresh the page — the state persists.

Verified live (as Manager): 4/6 → 5/6 → 6/6 (the send button appeared) → unmarked back to 5/6 → all of it survived F5. npm run verify is green (789 tests, +8 new).
