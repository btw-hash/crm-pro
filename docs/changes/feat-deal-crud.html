Deal CRUD: create / edit / delete

Branch feat/deal-crud · 298 tests green · typecheck + lint + format clean

What changed

  • Creating a deal — a "+ New deal" button on /deals (available to sales reps and the head of sales). Opens an in-app modal: client, name, goal, owner (defaults to the current user). The deal appears in the pipeline at the "Qualification" stage.
  • Editing — an "Edit" button on the deal page /deals/[id]. Opens an in-app modal with prefilled fields. Available to the owning sales rep and the head of sales.
  • Deletion — a "Delete deal" button on the same page → an in-app confirmation modal with the deal's name → a redirect to /deals after deletion. Available to the owning sales rep and the head of sales.
  • Clients cannot be created/edited — only selected from existing ones (the ERP owns clients).
  • Stage is not changed through CRUD — it's managed by the kanban board.
  • Clean architecture is respected: the domain has no next/react/infra, dependencies point inward. 298 tests green (+25 new: domain × 14, use-cases × 11).

Before → after

Before

Deals came only from the seed — none could be created, renamed, or deleted through the UI. Data was frozen at launch.

After

A sales rep or the head of sales creates deals right from the pipeline. The owning sales rep and the head of sales edit the name, client, goal, owner — and delete the deal with confirmation. All operations go through in-app modals, no browser prompt/confirm.

Repro steps

Scenario 1 — creating a deal

  1. Start: npm run dev → open http://localhost:3000/deals.
  2. Confirm you're logged in as a sales rep (default — Owens). The "+ New deal" button sits next to the "Deals" heading.
  3. Click "+ New deal" → an in-app modal opens (not a browser popup).
  4. Pick a client, enter the name "CRUD Test", pick the goal "Launch new SKU", owner — the current user (default).
  5. Click "Create deal" → the modal closed.
  6. The new "CRUD Test" card appears in the "Qualification" pipeline column.

Scenario 2 — editing a deal

  1. Open the just-created "CRUD Test" deal (click the card's name).
  2. Click the "Edit" button under the heading → an in-app modal opens with prefilled fields.
  3. Change the name to "CRUD Test — renamed".
  4. Click "Save" → the modal closed, the page heading updated.
  5. Return to /deals — the card shows the new name.

Scenario 3 — deleting a deal

  1. Open the "CRUD Test — renamed" deal.
  2. Click the "Delete deal" button → a confirmation modal appears with the deal's name.
  3. Confirm the text: "Delete deal 'CRUD Test — renamed'? This action is irreversible."
  4. Click "Delete" → a redirect to /deals.
  5. The "CRUD Test — renamed" card is gone from the pipeline.

RBAC: a technologist or a procurement officer doesn't see the "+ New deal", "Edit", "Delete" buttons. Log in as a technologist: username=kent, password=demo1234.

Edge case: deleting someone else's deal (sales rep Owens → Grant's deal) — the buttons don't show, and the server action also checks ownership.
