#212 Catalog 1000+: search + cart + key info

feat/catalog-search-cart · dev-b · 2026-06-26

What was done

1. Catalog search
  • A search field above the grid — filters instantly (client-side)
  • Searches by name and SKU, case-insensitive
  • Empty query → all products; no matches → a message
  • Ready for 1000+ items: filter before render, not virtualization
2. Cart (client-side)
  • A "+ Add to cart" button on every card
  • A counter in the "🛒 Cart (N)" button in the grid header
  • A drawer panel on the right: item list, +/−/✕, quantity
  • "Build list" → a text block to paste into a proposal
  • A "Copy" button → clipboard
3. Warehouse stock
  • Loaded from the ERP via getStockLevel in parallel for all items
  • Green: >50 units in stock
  • Yellow: ≤50 units (low, running out soon)
  • Red: 0 — out of stock
  • Gray "No data" — item not found in the ERP
4. Key info on the card
  • Stock 200 kg or Out of stock
  • Expiration Shelf life: 12 months
  • Benefits from the Sales Kit, RSP, margin (only for allowed roles)

Architecture of the changes

domain/product/product-search.ts — a pure function searchProducts(products, query). Filters by name+sku. TDD: 5 tests.
application/use-cases/list-products-with-stock.ts — use case listProductsWithStock(): loads products + their stock levels in parallel via Promise.all. TDD: 3 tests.
infrastructure/composition-root.ts — listProductsWithStock added additively to the container. Hot file — a minimal edit (3 lines).
app/products/_components/product-catalog.tsx — a new client component ProductCatalog: search (useState + searchProducts), cart (useState), drawer panel, list assembly.
app/products/page.tsx — replaces the direct grid with <ProductCatalog>; switched from listProducts to listProductsWithStock.

What's not included (scope cut)

  • Pagination/virtualization for 1000+ items — the client-side filter works fine for the seed (9 items), real 1000+ needs server-side search with pagination (separate issue)
  • Linking the cart to creating a proposal/order — the list is assembled as text for copying; calling buildProposalDraft directly requires a dealId (a separate deal-selection step)
  • Pack size — an attribute of the request, not the product, not stored in the Product domain
  • Dev verification in the browser — blocked by a Turbopack+Windows junction panic (Next 16.2.9 doesn't support junction node_modules); the code passed tsc + lint + 526 tests
