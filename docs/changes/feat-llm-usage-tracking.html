AI spend tracking — actual, per request

How many tokens and dollars go into each AI feature — visible in the new "AI spend" section

What changed (#401, building on #216)

  • For every model call the server now records the actual token spend (in / out / cached) + which feature triggered it, the model, and the time. Previously the provider's usage was thrown away, and the "cost" shown in the assistant was an underestimated client-side guess.
  • A new "AI spend" section (for the head of sales): a summary over a period + a "what we're spending on" table by feature, with cost in dollars.
  • The log is a separate telemetry channel: it writes only numbers and labels, no request/response text (GDPR/CCPA). Memory has a hard cap — it doesn't grow on the demo VM.

Before → after

AI spend Before After
Where the numbers come from An estimate from visible text length (underestimated), never saved The provider's actual usage for every call, in the log
Coverage Only the assistant, only the current screen session All 9 AI features (voice→act, letters, descriptions, assistant, …), persistent
Where to look A tiny caption under the assistant's reply The "AI spend" section: a summary + a per-feature table over 30 days
Storage — memory (ring buffer + aggregates, anti-OOM) or Postgres depending on mode

How to verify

  1. Log in as the head of sales (demo login "Alan Peterson").
  2. In the left menu (the "Tools" section) open "AI spend" — the coin icon.
  3. In stub mode (AI_MODE=stub) you'll see an honest empty state: "Tracking starts with the first AI call in live mode."
  4. On a stand with live AI (AI_MODE=live) ask the assistant a question, then return to "AI spend" — a row for that feature appears with tokens and cost.

⚠ For OpenAI, cached tokens don't come through the API (billing accounts for them on its own side) — the "Cached" column may not match the provider invoice.

Under the hood (for developers)

  • Interception — an outer decorator UsageTrackingLlmProvider; the feature label travels through LlmFeatureScope (AsyncLocalStorage, same as pseudonym-scope).
  • Storage sits behind ports LlmUsageSink / UsageReportRepository; in-memory and Prisma implementations (usage_records + usage_daily).
  • Writes are fire-and-forget, errors are swallowed — tracking never breaks the assistant's reply. Cost is computed from tokens deterministically (AI never invents it).
  • Flags: USAGE_TRACKING, USAGE_RETENTION_DAYS, USAGE_MEMORY_MAX_ROWS. Covered by ~45 tests (incl. an anti-OOM stress test).
