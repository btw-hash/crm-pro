[6] Client editing + all fields on creation

Before After
The creation form: only name, city, ein. No editing at all. A unified ClientFormModal in two modes:
— create: all fields (name, type, priority/category, city, EIN)
— edit: the same fields, prefilled with the client's data
An "Edit" button in the client card header.

What about legalEntities

The legalEntities field (an array of legal entities) was NOT added to the form — it requires a UI for dynamically adding/removing rows (a separate task). Only what's supported by single fields was kept in the form.

Repro steps (editing)

  1. Open the client card /clients/:id
  2. Click "Edit" (button in the header, next to "Open in ERP")
  3. Change the name, type, priority, city, or EIN
  4. Click "Save" — the client list and the card revalidate

Repro steps (creation with full fields)

  1. Open /clients (role head or mop)
  2. Click "New client"
  3. Fill in: name, client type, priority, city, EIN
  4. Click "Create client"

The "Segment" field — what it is

The "Segment" column in the client list displayed client.category (ABC classification: A/B/C), converted into a priority via clientPriority() (A→high, B→medium, C→low). On the client card it shows as "Category: Large · C" — that's category C with the "Large" label.
