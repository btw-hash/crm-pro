"Order → accounting" handoff memo

The missing link in the #128 end-to-end chain: the system automatically assembles the package accounting needs to process for the order — before it's handed off to the warehouse.

What was done

  • On the Shipments & delivery page (/shipments) the first document in the flow was added — the "Accounting handoff memo": what to process for the order before it's handed to the warehouse.
  • The document assembles itself from the order (passive capture): client details (EIN), order number, line items, weight, ship date, and the standard ERP document package to issue (Invoice · Packing slip · Tax invoice). The accountant doesn't need to retype the order by hand — that was the main pain point from the call transcripts.
  • Only orders in the "Placed" / "In accounting" stages make it into the memo — the ones that haven't gone to the warehouse yet. At the top — a counter of "orders to process" and the package's total weight.
  • Everything is deterministic from the data (not from AI). A pure domain function buildAccountingHandoff (domain/shipment/accounting.ts), wired into the existing use case getDispatchPlan alongside the warehouse memo and the summary report.

Where it sits in the #128 chain

Order (Manager) → Accounting · handoff memo → Warehouse memo → Summary report → Delivery schedule
The warehouse memo, summary report, and delivery schedule already existed; the first link — the handoff to accounting — was missing. Now the whole "order → accounting → warehouse → delivery" chain is assembled by the system as derived documents. The shipment stage in_accounting ("In accounting") already existed in the model for this — the handoff memo gives it meaning.

What's left behind the port (not in this PR)

Actually issuing the documents in the ERP (invoice/packing slip/tax invoice) and a return waybill for claims — behind the ErpGateway port and dependent on connecting the real ERP (#15, blocker — an anonymized copy of the database is needed, #1). The order write contract is already in place (ADR-0006). The handoff memo is the system-assembled source package for that issuance.

How to verify

  1. Open Shipments & delivery (/shipments) under an operational role (head of sales / procurement).
  2. The first section — the "Accounting handoff memo" with an "orders to process" counter and a table: order, client, EIN, line items, weight, ship date, document package.
  3. The rows show only orders in the "Placed" / "In accounting" stages; orders that have gone to the warehouse/delivery/been delivered are not shown in the memo (they've already gone through accounting).
  4. Move the order past "In accounting" with the "Next stage →" button (in the warehouse memo) — the row disappears from the handoff memo. This shows that the document reflects the current state of the flow.
