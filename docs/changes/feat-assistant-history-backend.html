Head of sales assistant: conversation history — backend

PR1 of 2 · Issue #338 · UI (on-screen history) — separate PR2

What changed

Backend for the head of sales AI assistant's memory: (A) the assistant now understands dialogue context — follow-ups like "any links?" / "any other options?" are now interpreted relative to the previous answer; (B) conversation persistence was added — saving, listing, opening, and searching history, private to the owner (RBAC). The assistant's system prompt was also strengthened — answers are now on-point and framed in Millbrook Foods' business context.

This is the server layer (domain/port/adapters/schema/use-cases/agent context). There's no visible history screen here — it's wired up in PR2.

Dialogue context in the agent AI behavior

Before

"Find bakeries in Denver" → a list. "Any links?" — the assistant didn't understand what this referred to, and answered as if it were a new, isolated question.

After

Previous dialogue turns are passed to the AI (a "PREVIOUS DIALOGUE" section in the prompt). "Any links?" is interpreted as a follow-up to the earlier answer about bakeries.

Conversation persistence data

Before

A conversation lived only in the current session and disappeared — you couldn't reopen the history or find a past answer.

After

Every "question → answer" exchange is saved. Available: a list of conversations (newest first, with a preview), opening a full conversation, searching message text. Other people's conversations are inaccessible (tied to the owner).

Business context and answer style AI behavior

Before

On "find clients / bakeries in the market," the assistant could drift into generic marketing advice and would paste raw links directly into the text.

After

The prompt now hard-codes: Millbrook Foods is an ingredients distributor, our clients are bakeries / confectioneries / HoReCa that we sell to. "Find clients" = searching for lead companies of that kind. The answer is specific found companies with a short relevance line, no raw URLs in the text.

How to verify (backend)

  1. From the project root, run npm run verify — typecheck + lint + format + tests should all be green.
  2. Dialogue context: the test src/application/use-cases/ask-manager-assistant.test.ts → the "(e) dialogue context" scenario checks that previous turns reach the AI planner.
  3. Persistence + RBAC: the tests in-memory-assistant-conversation-repository.test.ts and assistant-conversations.test.ts — creating a conversation from a question, updatedAt increasing, list sorting, substring search, and that a different owner gets null / an empty list.
  4. Strengthened prompt: ASSISTANT_PLAN_SYSTEM in src/infrastructure/ai/llm-ai-gateway.ts — Millbrook Foods' business context and answer style rules.
